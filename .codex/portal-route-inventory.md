# Portal Route Inventory

## Summary
- The portal lives entirely under `/portal/*`; the only exception is a handful of auth paths (`/portal/forgot-password`, `/portal/password-reset`, etc.) before the main portal router.
- `App.jsx` wraps the entire portal subtree in `PortalLayout` which sits inside an `ErrorBoundary` that prefixes codes with `PORTAL-ROUTE` and forces navigations to `/portal/client-portal` when hitting `/portal`.
- Each portal route is guarded by `FeatureRoute`, `RequirePermission`, or explicit role checks, and navigation data comes from `src/lib/rbac.js` (which already groups entries by logical modules such as Scheduling, CRM, and Compliance).

## Navigation Grouping Sources
- `src/lib/rbac.js` seeds navigation entries in logical blocks: Dashboard, Clients/CRM, Scheduling, Guards, HR/Compliance, Payroll, Reports, Audit, AI, User Management, Settings, Client Portal.
- Each block checks permissions via `hasPermission` or `hasAnyPermission` so menu grouping aligns with roles.
- Guard-specific entries (My Schedule, Open Shifts) are conditionally pushed for guards, ensuring menu grouping stays meaningful.
